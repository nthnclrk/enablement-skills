# Talk Track Framework

Use this reference to create usable talk tracks that drive better decision quality, not just better phrasing.

## Track Design Principles

- One call objective per track.
- One concrete next-step commitment.
- Persona language over product language.
- Proof statements are short and specific.
- Branch logic is explicit for likely turns.

## Core Track Structure

1. Opening frame
2. Context check
3. Diagnostic questions
4. Value bridge
5. Proof insert
6. Objection branch handling
7. Next-step close

## Variant Selection

Use one primary variant per output:

- Discovery: diagnose business impact and buying urgency.
- Demo: validate fit against agreed outcomes.
- Commercial: manage value-to-price tradeoffs and procurement friction.
- Renewal/Expansion: connect outcomes to continuity, risk, and growth path.
- Manager inspection: assess whether reps are improving execution quality.

## Branch Logic Template

For each high-likelihood turn, define:

- Trigger signal
- Diagnostic line
- Response path
- Proof insert
- Recovery close

Recommended branch set:

- Skeptical stakeholder challenge
- Competitor claim
- Pricing pushback
- Procurement/compliance concern

## Proof Insert Rules

- Keep each proof insert under 20 seconds.
- Prefer quantified customer outcomes where possible.
- If evidence is directional, label it as directional.
- Do not use unverified claims in commercial tracks.

## Landmines

- Overclaiming implementation speed or scope.
- Jumping to demo before diagnostic depth.
- Using one persona's language for all stakeholders.
- Ending without a concrete owner and next-step date.

## Output Pattern

Minimum output should include:

- Track objective and target role/persona/stage
- Full conversation flow
- Branch cards for likely turns
- Proof snippets with source confidence
- Next-step ask language
- Manager inspection checks
