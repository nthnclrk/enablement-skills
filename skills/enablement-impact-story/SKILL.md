# Enablement Impact Story

Build a credible impact narrative that leadership can use for decisions.

## Confirm Inputs First

Confirm:

- Initiatives in scope
- Baseline and current performance data, including population, denominator, and metric definition
- Measurement and comparison period
- Audience and decision context
- Known confounders and any comparison or counterfactual evidence
- For financial ROI: verified incremental costs, monetized benefit inputs, time horizon, and attribution assumptions
- Supplied current context or relevant sections of `.enablement/context.md`, when available; stale, inferred, or conflicted material remains provisional

If critical evidence is missing, ask for the smallest set needed to avoid speculative claims. Default to an observed-results or contribution narrative; do not label the output ROI when financial inputs are incomplete.

## Read The Right Reference

Read [references/impact-story-template.md](references/impact-story-template.md) before drafting.

## Default Workflow

1. Set the evidence boundary from supplied current context and source material; keep provisional context out of factual or causal claims.
2. Choose the strongest defensible claim mode: observed result, contribution, causal effect, or financial ROI.
3. Define the decision context, population, metric definitions, baseline, comparison period, and time horizon.
4. Validate source freshness, denominator consistency, comparison fitness, and known confounders.
5. Show absolute and relative movement, then separate observation from interpretation.
6. Build the contribution chain from enablement action to behavior change to business outcome.
7. If ROI requirements are met, calculate gross benefit, total incremental cost, net benefit, ROI, and sensitivity range using the reference method.
8. State confidence, assumptions, and limits beside each material claim.
9. Add decisions to make now, options, trade-offs, and owner-ready next actions.

## What To Avoid

- Overstating causality when the evidence is directional.
- Calling pipeline influenced, activity completion, or an unmonetized outcome “ROI.”
- Mixing populations, denominators, currencies, or time horizons in one comparison.
- Burying critical caveats in appendix notes.
- Failing to convert the story into clear leadership decisions.
- Mixing observation and recommendation in the same claim.

## Tool Notes

- Keep narrative structure tool-agnostic.
- If needed, adapt output into the user's memo, slide, or dashboard workflow.
- Return a reviewable draft by default. Do not publish, send, or write the artifact into an external system without explicit user approval of the exact artifact and destination.

## Output Contract

Default output includes:

- Executive summary narrative
- Claim mode and why the evidence supports it
- Evidence table with confidence labels
- Assumptions and limits section
- Financial analysis with formulas and sensitivity range only when ROI requirements are met
- Decisions to make now with options and trade-offs
- Recommended next actions
- Optional appendix outline for deeper review

## Quality Bar

- Story is evidence-led and avoids overclaiming causality.
- Every change claim uses consistent definitions, populations, denominators, and time periods.
- Financial ROI appears only when both incremental cost and monetized attributable benefit are supportable.
- Confidence levels are explicit and defensible.
- Leadership can act on the recommendations immediately.
- Narrative remains concise while preserving key caveats.
- Decision options are explicit enough for sponsor-level review.
