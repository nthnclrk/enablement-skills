# One Pager And Slide Outline

Turn messy source input into a clear one-pager and slide-ready structure that teams can use quickly.

## Confirm Inputs First

- Use supplied current context or relevant sections of `.enablement/context.md` when available. Treat stale, inferred, or conflicted material as provisional; never update shared context silently.
- Confirm audience and use context.
- Confirm single primary objective for the artifact.
- Confirm source materials, source authority, and evidence quality.
- Confirm the exact output branch: one-pager, slide outline, or both.
- Confirm length or slide-count constraints, delivery channel, and any voice or brand rules.
- Confirm whether the output is internal, customer-facing, or partner-facing and which claims are approved for that audience.
- Confirm whether this is net-new narrative or a rewrite.
- If inputs are incomplete, ask for only blocking items. Label interpretation and assumptions, but never invent evidence or approved claims.

## Read The Right Reference

- Read [references/narrative-outline-template.md](references/narrative-outline-template.md) when you need the default structure and section-level constraints.

## Default Workflow

1. Select the requested output branch before drafting.
2. Build a compact source and claim register: confirmed fact, interpretation, implication, source, and approval status.
3. Define one audience-specific thesis, one primary ask, and the evidence needed to support them.
4. Adapt the narrative to the job: executive decision, seller action, partner execution, launch understanding, or internal alignment. Change the information hierarchy, not only the tone.
5. For a one-pager, draft only the one-page flow: assertion, context, problem, approach, proof, decision or action, and next steps.
6. For a slide outline, draft only the slide sequence: one assertion headline, evidence cue, and speaker intent per slide.
7. When both are requested, reuse the same evidence spine while tailoring each artifact to how it will be consumed.
8. Add appendix topics only when they protect the core narrative from unnecessary detail.
9. Run a final claim, audience-safety, length, and next-action check.

## Output Contract

Always include an evidence map for core claims and a short list of unresolved assumptions or approval gaps.

- If `one-pager` is requested: deliver the one-page narrative brief only.
- If `slide outline` is requested: deliver the assertion-led slide outline only.
- If `both` are requested: deliver both from one shared evidence spine.
- Include audience variants or appendix topics only when requested or materially useful.

## What To Avoid

- Mixing multiple objectives into one overloaded narrative.
- Producing topic-label slides instead of assertion headlines.
- Reusing one audience voice across exec, seller, partner, and launch contexts.
- Producing both artifacts when the user requested only one.

## Quality Bar

- Narrative has one dominant argument with no competing storyline.
- Slide headlines are assertions, not topic labels.
- Evidence supports each major claim.
- Output is concise enough for rapid stakeholder review.
- Next actions are explicit and owner-ready.
- The selected artifact fits the stated channel, audience permissions, and length constraint.
