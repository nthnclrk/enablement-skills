# Onboarding Program Builder

Design onboarding that builds real job competence and faster time to first performance.

## Confirm Inputs First

Confirm:

- Use supplied current context or relevant sections of `.enablement/context.md` when available. Treat stale, inferred, or conflicted material as provisional; never update shared context silently.
- Target role and segment
- Experience profile mix (new hire, internal transfer, experienced external hire)
- Job-critical tasks, expected outcomes, and costly failure risks
- Target time to supervised and independent performance
- Known competencies or role standards, if they exist
- Starting-proficiency evidence available for each learner profile
- Available training assets
- Cohort size and timing, learner protected time, facilitator and SME capacity, geography or timezone constraints, delivery-system constraints, and manager coaching capacity
- Any formal certification that onboarding must prepare for without scoring itself

If missing data blocks design, ask for only those items. Use labeled assumptions only for reversible phase or sequence choices; keep role standards, proficiency evidence, ramp targets, capacity, and certification requirements unknown until verified.

## Read The Right Reference

Read [references/onboarding-framework.md](references/onboarding-framework.md) before drafting the plan.

## Default Workflow

1. Derive competencies from the role's critical tasks, expected outcomes, and failure risks; do not begin with the course catalog.
2. Establish a lightweight starting baseline and use it to vary support for new hires, internal transfers, and experienced hires.
3. Define outcome-gated ramp phases for foundation, supervised application, and independent execution. Add a 30-60-90 calendar view only when requested or operationally useful.
4. Map each competency to practice, live-work evidence, and a diagnostic manager checkpoint.
5. Build a recurring learn, practice, apply, review, and reinforce loop.
6. Build a capacity ledger across learners, facilitators, SMEs, managers, systems, and geography. Return `fits`, `reduce`, `sequence`, or `blocked` and adjust cohort or scope before assigning work that exceeds the envelope.
7. Assign manager actions that fit available coaching capacity.
8. Define observable ramp-risk triggers, targeted remediation, and the evidence needed to return to the normal path.
9. If a formal certification exists, show where onboarding prepares and gathers evidence for it, but leave pass/fail standards and assessor decisions to `certification-program-builder`.

## Tool Notes

- Keep the plan tool-agnostic.
- If the user has an LMS or wiki, map learning and diagnostic checkpoints into the existing system without treating content completion as proof of readiness.

## Output Contract

Default output includes:

- Outcome-gated ramp plan, with a 30-60-90 view only when requested or useful
- Experience-level variant notes by role profile
- Job-task, competency, practice, and evidence matrix
- Weekly manager check-in agenda
- Diagnostic evidence tracker that does not make formal pass/fail decisions
- Ramp-risk intervention plan
- Certification preparation handoff when a formal certification is in scope
- Capacity ledger and fit/reduce/sequence/blocked delivery decision

## Quality Bar

- Plan is role-specific and tied to observable outcomes.
- Variant paths are realistic for different experience profiles.
- Practice and reinforcement are built into each phase.
- Manager responsibilities are explicit and lightweight.
- Diagnostic checkpoints use observable evidence and remain separate from formal certification decisions.
- The plan accommodates reasonable accessibility needs and does not confuse style, confidence, or familiarity with competence.
