# Objection coding judgment

Use this when you are coding calls or deciding whether a theme is recurring. The skill body has the procedure. This file does not write approved responses.

## This is a brief, not a library

Cluster buyer concerns. Rank them. Recommend the next research or enablement move. Stop.

**Fails.** "Approved response: 'Implementation is a proven, low-risk motion with dedicated CSM support.'"

**Passes.** "Implementation capacity in 6 of 18 usable discovery calls across 4 accounts. Buyer language: 'we do not have anyone to own the rollout.' Consequence: extra validation. Next: proof of implementation staffing, then a governed response in `objection-library-builder`."

## Unit of analysis

- Eligible conversation is the denominator for prevalence.
- Count a theme at most once per conversation for prevalence.
- Track extra mentions separately as intensity or response failure.
- Exclude unusable sources from the denominator and say why.
- An unmentioned objection is `not observed in available evidence`, not disproved.

Recurring means at least two independent accounts unless the user set a different rule.

## Code the buyer's concern

Capture source ID, date, account, rep or team, segment, persona, call type or stage, then:

- `explicit objection`, `implied concern`, `buyer question`, or `seller interpretation`
- short excerpt or precise paraphrase
- seller response and buyer reaction, when present
- observed consequence, when present
- type, root-cause hypothesis, notes

Types: `Value`, `Priority`, `Product Fit`, `Implementation Risk`, `Trust`, `Commercial`, `Change Cost`, `Decision Alignment`.

Apply more than one type only when the evidence contains genuinely distinct concerns. Code the underlying issue, not the seller's favorite rebuttal.

## Impact

- `Blocking`: the buyer conditions or stops progress on the concern
- `Material friction`: extra validation, delay, escalation, or a requested concession
- `Open concern`: raised, effect not established
- `Unknown`: the source does not show the consequence

Do not infer causation from a later stall or loss without corroborating evidence.

## Root cause stays a hypothesis

`message_gap`, `proof_gap`, `process_gap`, `product_gap`, `commercial_mismatch`, `competitive_pressure`, `stakeholder_misalignment`.

A product objection can still originate in proof, positioning, or process. Label the cause as a hypothesis unless direct evidence supports it.

## Confidence

Score from four visible factors: recurrence across independent conversations, source fidelity, representation across the intended slice, and consistency of buyer language plus consequence.

Use `high`, `medium`, or `low` only after stating the reasons. Do not invent a universal call-count threshold.

Show unique call, account, and rep or team coverage so one source concentration is visible. Prefer counts over percentages for small samples. Keep an isolated signal off the recurring-theme ranking.

## Thin evidence

If most records are summaries, weight transcripts higher and lower the confidence. If one account supplies half the mentions, report unique-account recurrence beside call prevalence. Do not write the library from that set.
