# Stage Exit Framework

Use this reference to design stage definitions that are inspectable and forecast-usable.

## Stage Card Template

For each stage, define:

- `purpose`: what risk is reduced at this stage
- `entry_criteria`: minimum conditions to enter stage
- `exit_criteria`: evidence required to progress
- `required_proof`: fields, notes, or artifacts required
- `owner`: who confirms progression validity
- `anti_patterns`: common bad transitions to block

## Evidence Principles

- Prefer customer-validated evidence over rep activity.
- Require at least one stakeholder and one business-case signal before late-stage progression.
- Avoid criteria that can be "completed" without deal health change.

## Qualification Anchors

Use qualification elements as evidence checks where relevant:

- economic buyer clarity
- measurable pain and impact
- decision process and timeline clarity
- competition/status quo position
- champion strength
- implementation feasibility

## Governance Minimum

- Define exception process for forced stage movement.
- Define weekly manager inspection checklist.
- Define monthly RevOps audit sample.
- Define rollback rule if new criteria reduce data quality.
