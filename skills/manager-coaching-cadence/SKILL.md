# Manager Coaching Cadence

Build a coaching rhythm that managers can actually run every week.

## Confirm Inputs First

Confirm:

- Use supplied current context or relevant sections of `.enablement/context.md` when available. Treat stale, inferred, or conflicted material as provisional; never update shared context silently.
- Team role mix and performance context
- Top 2-3 coaching priorities tied to observable behaviors
- Existing manager meeting cadence and current inspection rhythm
- Available evidence sources and quality (call data, deal reviews, CRM, manager notes)
- Manager span, protected coaching time, existing obligations, and required rep coverage
- Team type (SMB velocity, mid-market, enterprise, post-sale) for cadence tailoring
- Employee-data boundaries: approved evidence, who may access notes, retention expectations, and where formal performance management begins

If key data is missing, ask for only what is needed to design a workable cadence. If target behaviors or usable evidence are unknown, return a short observation-baseline plan first rather than presenting a full cadence as ready.

## Read The Right Reference

- Read [references/manager-coaching-cadence-template.md](references/manager-coaching-cadence-template.md) before producing final cadence assets.

## Default Workflow

1. Pick the 2-3 behaviors you want to improve and the signals that prove they happened.
2. Calculate a capacity envelope from protected coaching time, preparation, session, follow-up, and required coverage. Prioritize individual coaching where evidence shows the greatest need; use group reinforcement for shared gaps and rotate the remaining coverage.
   State the assumed evidence-review volume and tooling. If the review work cannot fit, reduce the sample or change the coverage model rather than compressing it invisibly.
3. Choose a cadence pattern that fits the team type, existing operating rhythm, and capacity envelope. Treat newly designed weekdays and commitment deadlines as proposals unless the user supplied them. Do not invent numeric promotion, persistence, or escalation thresholds—even as convenient pilot defaults; use a qualitative decision condition and name who must confirm a threshold if one is needed.
4. Build the recurring loop with explicit time budgets for evidence review, coaching, and follow-up.
5. Create a manager agenda and an observation log that captures only role-relevant evidence.
6. Track rep commitments with owner, due date, and proof of follow-through.
7. Add a trend review at a frequency supported by evidence volume, separating skill gaps from pipeline, territory, or process problems.
8. Define when managers should escalate for enablement support and when an issue must move into the organization's formal performance or People process.
9. Produce a rollout plan managers can start using right away.

## Tool Notes

- Keep coaching cadence tool-agnostic.
- If call intelligence or CRM is available, use those systems as evidence inputs but keep the workflow usable without them.
- If evidence quality is low, reduce conclusion strength and increase direct observation frequency before major interventions.
- Do not use protected characteristics, health or family information, unrelated private communications, or opaque automated scores as coaching evidence. Give the rep a way to add context or correct the record.

## Output Contract

Default output includes:

- Weekly coaching cadence schedule by manager
- Session agenda template and coaching-question prompts
- Observation log template for calls/deals/behavior checkpoints
- Rep commitment tracker with due dates and verification signals
- Capacity and coverage rationale
- Trend review template and interpretation guidance
- Escalation guidance for persistent gaps
- Implementation notes for the initial rollout window
- When evidence is not yet usable, an observation-baseline plan with owner, sample, review point, and the decision needed before cadence design

## Quality Bar

- Cadence is sustainable for real manager workloads.
- Capacity includes realistic evidence-review time, generated schedule choices are labeled proposed, and unsupported numeric escalation rules remain unresolved rather than being invented.
- Coaching targets behavior change, not generic feedback.
- Follow-up is explicit so sessions connect over time.
- Output can be run immediately with minimal setup.
- Distinguish skill/coaching issues from process, territory, or pipeline-health issues.
- Keep coaching records separate from formal performance records unless an authorized process explicitly requires the transition.
- Do not make consequential performance decisions from one interaction, one automated score, or evidence the rep cannot review.
