# Source system guide

Use this when the inventory is pulled from a content system, wiki, or field-signal channel instead of being assembled by hand.

## Useful inputs

Content repositories: stable asset ID, canonical location, owner, type, audience, status, last reviewed date, and usage with an eligible-audience denominator.

Wikis: source-of-truth pages, taxonomy, permissions, search or findability signals, linked assets, update history.

Field signals: recurring asks, repeated searches, workflow blockers, and independent source count.

## Minimum pull

Stable asset ID, title, canonical location, owner, audience or role, stage or job, publication status, last reviewed date, usage numerator and eligible-audience denominator when available, plus evidence source and date when demand is qualitative.

## Handling

Classify the problem before calling it a gap: missing, weak, stale, low discoverability, or fragmented duplicates.

Keep low-usage interpretation conservative unless discoverability and freshness are known. Separate content-creation work from taxonomy and governance work. Preserve value, confidence, and effort as separate fields.

**Fails.** Treating failed-search volume as consumption, or treating an enterprise calculator as mid-market coverage.

**Passes.** Failed search plus a current approved asset → discoverability. Enterprise-only plus a mid-market job → create or adapt, not "already covered."

## Writeback

Do not retire, relabel, or republish automatically. Output the backlog first. System changes wait for explicit approval of the exact targets.
