# Escalation Rules 2.0 Release Notes

All details below are fictional and sanitized.

## Release Frame

- Product: MosaicOps
- Technical availability: 2026-08-18
- Eligible plans: Pro and Enterprise
- Availability: enabled for new eligible workspaces; existing eligible workspaces can opt in
- Customer-facing field announcement: managed separately by Go-To-Market

## What Changed

1. Conditional triggers can combine handoff age, priority, and team.
2. Team escalation can notify a named queue instead of one individual.
3. Audit history records rule changes and escalation events.
4. Existing legacy rules continue to run without immediate migration.

## Migration

- Migration is optional until 2026-12-15.
- New customers will use the new rule builder from 2026-09-15.
- Existing customers can migrate rule by rule.
- There is no automatic conversion for custom script-based rules.

## Limitations

- Starter plan is not eligible.
- Custom ERP event triggers require a services and solutions-engineering review.
- Mobile push notification support is planned later and is not part of this release.
- The feature does not guarantee that operational incidents will be prevented.

## Approved Proof

- In a four-customer pilot, median assignment time for escalated handoffs improved by 35% over 45 days.
- The result is directional, based on four customers, and is not an industry benchmark or guaranteed outcome.

## Approved Positioning

Escalation Rules 2.0 helps operations teams inspect and route overdue handoffs with less manual monitoring.

## Escalation Paths

- Eligibility or roadmap: Product
- Custom integration feasibility: Solutions Engineering
- Migration support: Customer Success
- Pricing or packaging exception: Finance and Deal Desk
